Berserker 7 · Milestone retro 3: netcode

Written 19 November 2026. Covers 19 November 14:27 to 23:12 UTC, from the merged Sandbox (PR #74, the end of retro 2) to the outdated-build notice (PR #92). Live build 23e5d03. Screenshots come from the lanes' local builds and from the project owner's markup on the mockup.

In one paragraph: Berserker 7 is now a two-player online game. A host gets a room code from the debug panel, and a second player joins from the main menu's Multiplayer item or an invite link. Both play the Sandbox together over a direct WebRTC connection (PeerJS), or across two tabs with ?net=local. The host runs the game and sends snapshots; each player's own movement is predicted and the other player is interpolated. A first test between the project owner and a friend over the internet worked, with the owner hosting from behind carrier-grade NAT. Messages are now MessagePack bytes (43% smaller than JSON for the host's traffic), the debug panel shows the connection type, and the main menu tells players when a newer build is out. Earlier in the session, the mockup's perspective was measured from the owner's markup and turned into a second blockout with a smaller player, and the menus gained open and close animations.

Decisions made

DecisionDetail
Block size from the artOne gameplay tile is one block as the owner reads it from the mockup's textures. On the second blockout the player is 0.55 × 1.2 tiles, from the owner's drawn collision boxes. The final character and tile sizes wait for placeholder textures and sprites.
Maps set base camera values (T-107)Each map sets its base FOV, offset, zoom, aim follow and smoothing, overriding the game defaults. Events and triggers layer on top at run time and never replace them.
Map editor (T-108)A draft is planned; details to be decided. The idea came from editing cubes against an overlay of the art.
Networking model (T-109)The host runs the game and sends snapshots (30 a second); the guest sends inputs (60 a second). Each player's own movement is predicted and reconciled; the other player is interpolated. Chosen over lockstep and rollback because it doesn't need bit-exact determinism: each snapshot corrects the guest.
World prediction later (T-110)Once enemies exist, the guest re-runs the game forward from the latest snapshot, capped at about 250 ms, with corrections eased in.
Two-player testing (T-111)Every new feature is built and checked with a host and a guest.
Design for delay (D-129)Telegraph attacks longer than the worst delay, spawn off-screen or behind an animation, use generous hitboxes for fast enemies, scripted platforms, host-decided pickups.
Wire formatMessagePack with msgpackr, from the benchmark. Next: fewer packets, then integers with fixed point in the simulation. If positions go coarse, the simulation itself uses the same grid, not only the wire.
Signalling and relayThe public PeerJS signalling server, then a direct WebRTC channel. A TURN relay (T-047) only if real players need it; the connection-type line will tell.
Menu timingsPanel line 0.3 s, height 0.3 s, items 0.2 s. Game start: close 0.8 s, wait 0.5 s, 2 s to black, 1 s in.

Reading the mockup

The owner marked the mockup with red block squares, a green ground line, yellow perspective lines and a 1 × 2 floor tile. Measured against MoGe's depth, six of seven red squares are the same real size (1.55 m) at depths 10 m apart. The yellow lines meet within 2 px at (995, 415), so the camera is level (MoGe estimated 8.7° down), and the floor tile gives a focal length of about 400 px, a vertical FOV of about 91°. The owner's blue lines on the gantry and right-hand blocks each meet at a different point, so the image mixes local perspectives, as AI images often do.

The on-the-wire column is calculated, not measured: 85–113 B of IP, UDP, DTLS and SCTP headers per packet, at 90 packets a second, plus SCTP acknowledgements. That overhead (about 8.4 kB/s) is bigger than any codec saving, so sending fewer packets (inputs 30 a second, two ticks each) is the next lever. Every format encodes and decodes in about 1.1 µs or less per message.

Process

  • Owner tests before merge: each networking lane notified the orchestrator as soon as ?net=local worked, and the dev server was switched to its worktree so the owner could try it before review finished.
  • Review rounds capped: networking lanes ran at most two r9000 rounds; leftover findings were listed and fixed in a separate small lane (#84) instead of looping.
  • Benchmarks on the owner's go: the benchmark lane prepared a dry run, stopped, and ran the full timed run only after the owner said go.
  • Measure, then decide: MessagePack, the bundle cost and the packet overhead were all measured or calculated before the format changed.
